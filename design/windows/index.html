屏幕切换

Windows 客户端界面设计 · 设计稿 v2

窗口 440 × 600 Fluent · 浅色 托盘常驻

这是一个一次点击、然后立刻消失的工具：用户 99% 的时间只在托盘上，窗口只在「确认状态 / 改热键」时才打开。 所以界面不做仪表盘，只回答三个问题——现在画面在哪台机器、按一下会切到哪、上次切成功了吗。 两台机器用 Windows / Mac 官方图标 + 亮灯 / 灭灯两态表达「谁在用」，不用读文字也能判断。

布局逻辑

为什么把「状态」做成最大的一块

用户按完热键，画面已经切到另一台机器了，窗口根本看不见。等回到这台机器时，第一件想知道的事是 「我现在按下去会去哪」——所以「当前在哪」用 31px 大字，紧随其后的按钮直接写出目标机名 （切换到 Mac），而不是抽象的「切换」。

按钮文案永远等于目标，不写「切换屏幕」：切错方向的成本是黑屏 3 秒 + 摸键盘，比多读两个字贵得多。

信息的三个层级

L1 状态当前主机 + 输入源值，一眼可见
L2 动作主按钮 + 两台设备卡（可直接点对端切过去）
L3 排障探测 / 日志 / 诊断，收进列表，不抢视觉

为什么用「亮灯 / 灭灯」

两台机器的状态本质是二元的，指示灯最省认知：亮着的那台，就是画面所在的那台。 灯用绿色，和显示器、路由器上那颗电源灯一个语言，用户不用学。

不只靠颜色区分：灭灯那台同时做了去色、降低不透明度、换灰底、文案变弱四件事， 色弱用户靠明度和图标形状同样能判断。指示灯本身也有「发光 vs 内凹」的质感差。

交互约定

· 关闭窗口 = 收进托盘，不退出；退出只在托盘菜单里。

· 切换进行中按钮进入禁用态（800 ms 去抖），避免连点造成 DDC 队列堆积。

· 窗口不抢焦点：热键触发时只更新托盘气泡，不弹窗。

设置的原则

只暴露改得动的字段

config.json 里有 20 多个字段，界面上只放 9 个。剩下的（ ddc_backend、command_template、readback.*）留给高级分页的 「打开配置文件」入口——它们是排障参数，不是日常设置。

危险值就地解释

输入源映射旁边直接写清「实测 HDMI 17 / USB-C 18，27 会被拒绝」。 这一条能省掉未来 90% 的「切了没反应」求助——因为 27 是网上流传的标准值， 而这台显示器偏偏不认。

保存即生效

热键与显示器配置改完立即重建热键线程，不需要重启进程；DDC 后端变更会提示「需重启」。保存失败时字段级红框 + 顶部横幅，不弹模态框。

换一个组合键，或改用「严格右 Alt」避开冲突。

刻意不做的提示

切到 Mac 之后，Windows 侧的回读必然失败（显示器已从系统消失），这是预期行为，不弹任何提示、只写日志。 同理，热键重复触发的去抖、回读超时，都不打扰用户——这个工具的信噪比，就是靠「该沉默时闭嘴」换来的。

图形（沿用你提供的插画）

两台显示器一深一亮、两条弧形箭头首尾相接 —— 画面在两台机器之间来回换，语义比抽象箭头更直白， 也和主窗口里的两张设备卡形成了呼应。

源图是白底 JPG，已抠成透明底：按亮度 + 饱和度双判据算 alpha（纯白→透明、浅蓝机身→保留、柔和投影→半透明）， 而不是简单按白色泛洪，否则机身和箭头会被一起吃掉。

尺寸策略（一个诚实的提醒）

母版 1024px → 各尺寸 Lanczos 降采样，≤128px 补一道轻锐化，抵消缩小的糊。

16px 下细节会丢：两张屏和箭头会糊成一个蓝块，但深浅对比还在，任务栏里仍能认出是这个应用。 如果托盘里要求像素级清晰，可以再单独做一个 16/20px 的单色简化版（双屏轮廓 + 一条箭头）， 需要的话我加一档，不影响其他尺寸。

实现建议（不改现有架构）

现有 app.SwitchController / config / ddc 全部不动，只加一层 ui/： PySide6 画窗口（QSS 按上表取值），托盘继续用 pystray，窗口与托盘共用一个 controller，切换结果通过回调更新界面。 也可以把本页当 HTML 规格，用 pywebview 直接渲染——但托盘必须留在 Python 侧。

需要新增的只有三个接口：controller.switch_now() 的返回值（已有）、 backend.list_monitors()（已有）、config.save()（已有）。UI 不碰 DDC。
