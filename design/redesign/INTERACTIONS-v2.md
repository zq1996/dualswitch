**打开方式按类型分派**（用户确认：不是所有都用访达）：

| 类型 | 行内/预览窗动作    | 实现                                                                      | 理由                 |
| -- | ----------- | ----------------------------------------------------------------------- | ------------------ |
| 图片 | **用图片预览打开** | `NSWorkspace.open(_:withApplicationAt: Preview.app)` 或 `QLPreviewPanel` | 图片消费场景是「看图」不是「管文件」 |
| 文件 | **在访达中显示**  | `NSWorkspace.activateFileViewerSelecting`                               | 文件要的是定位/拖拽/后续操作    |
| 链接 | 打开链接        | `NSWorkspace.open(url)`                                                 | —                  |
| 文字 | 仅复制         | 写回 NSPasteboard                                                         | —                  |

**跨系统合理性**（用户问「两个系统的推送剪贴板，这样合理吗」的结论）：

- 契约 `CLIPBOARD-SYNC-CONTRACT.md` P2 明确 **文件/目录不跨端同步**，只有文字+图片在同步  
  （`ClipItem.kind: "text"|"image"|"mixed"`）。
- 因此：**图片**可能来自对端（内存 PNG payload，无本地路径）→ 用「图片预览打开」合理  
  （预览窗渲染的是 payload，预览打开走临时文件或 QLPreviewPanel）；  
  **文件**条目只可能是本机产生的（对端文件根本不过来）→ 「访达显示」合理，因为文件本来就在本地。
- 若未来 P2 落地文件同步，接收方需要落地到缓存目录，届时「访达显示」指向缓存路径，  
  语义仍然成立。

**用户反馈修正**：角标是**来源系统**不是来源应用 —— 从 Mac 复制的显 Mac 角标，  
Windows 复制的显 Windows 角标。应用名（微信/Safari…）降级为元信息行文字。

### 3.4 悬浮预览窗 🆕（用户反馈三轮修正定稿）

**触发**（Frset 源码/字符串证据）：

- 只在**缩略图**上悬停触发 —— 原文 `Show preview when hovering over clipboard icons`  
  =「悬浮在剪贴板**图标**上时展开预览」，**不是整行**（整行悬浮会误触发+遮列表）
- 打开延时 **450ms**：Frset 用 `hoverPreviewOpenDelay` + `__hoverPreviewOpenWorkItem`  
  （DispatchWorkItem 延时）；关闭延时 220ms（`hoverPreviewCloseDelay`）
- 预览窗本身 hover 可停留（`__isPreviewPopoverHovered`）；滚动/换页/换行立即关

**位置**：气泡放缩略图**左侧**，箭头朝右指向缩略图 —— 不遮挡右侧列表文字。  
左侧放不下才翻右侧；垂直方向箭头对准缩略图中线；超出视口自动夹紧。

**尺寸**（Frset：`MainPanelPreviewContentSizePreferenceKey` / `MeasuredSize`）：  
**随内容自适应，不是固定宽**。分类上限：

| 类型  | 自适应   | 窗口尺寸（clamp 上下限，§10.23）                                   |
| --- | ----- | -------------------------------------------------------------- |
| 图片  | 按原图比例 | **346×226 ~ 562×626**（内容框 522×477）；只缩不放（`imagePreviewMaxPopoverHeight`） |
| 文字  | **随行数长高** | max-width 392 / 高度上限 = min(屏幕可用高−120)（§10.20）           |
| 代码  | **随内容长高** | max-width 400 / 高度上限同上                                     |
| 文件卡 | 随文件名  | max-width 380                                                  |
| 链接块 | 随 URL | max-width 380                                                  |

**动画**（Frset：`SwiftUI Animation.spring(response:dampingFraction:)`）：  
弹簧入场 320ms `cubic-bezier(.22,1.2,.36,1)`，scale .9→1.015 过冲→1，transform-origin 朝锚点侧。

**视觉**：带**指向箭头**的气泡（Frset：`PopoverArrowShape`/`PreviewArrowGeometryStore`），  
r13 三层阴影、头部浅底+类型图标+状态药丸、代码块浅底描边、链接浅蓝块、底栏元信息+按钮。

## 8. 图标来源与提取（2026-10-21）

**背景**：用户反馈原型手绘 SVG 图标丑，「人家按钮都用的图标」。Frset 的图标在
`Assets.car` 里是矢量资产（REA `inspect-asset-catalog` 报 101 个资产名 / 320 条 rendition）。

**提取方式**：`icons/extract_car.py` —— pyobjc 加载 `CoreUI.framework` 私有接口，
`CUICatalog.imageWithName_scaleFactor_()` 取 `CUINamedImage` → `cgImage` → ImageIO 写 PNG。
20 个图标导出在 `icons/frset-extracted/`（clipboard_type_* / abc_* / settings_*）。

注意：Assets.car 内的 SVG 是差分压缩的，直接正则抽出来是乱码（踩过），
必须走 CoreUI 渲染。`icons/b64.py` 转 base64 → `icons-data.js` → `icons/inline_icons.py` 内联进原型。

**原型现状**：剪贴板文字/链接缩略图、空态插画已换 Frset 提取图。

**⚠️ 正式实现红线**：提取图仅供**设计原型比对**。`src/dualswitch/ui/assets/` 里的正式图标
必须**自己重绘**（描边粗细/圆角/光学重量参照提取图），不能把 Frset 的 PNG 直接打进产品包 ——
那是它的版权素材。平台角标（apple/windows）用 `icons/make_icons.py` 自绘那套。

### 10.5 图形分两类：截图 vs 图片文件

| 来源 | 列表缩略图 | 标题 | 元信息 |
|---|---|---|---|
| 截图（`com.apple.screencaptureui`） | 截图本身 | `图片 W×H` | `Mac · 截图 · …` |
| 访达复制的图片文件（`public.file-url`） | **读取文件生成的预览图**（最长边 ≤1600） | 文件名 | `Mac · 访达 · …` |
| 对端推来的图片 | payload 本身 | `图片 W×H` | `Windows · [对端应用] · …` |

实现：`clipboard/macos.py` 在 `public.file-url` 指向图片文件时用 ImageIO 抽缩略图，
`path` 记原路径（不上网）；点「预览」直接用原文件打开。

### 10.6 元信息行加「来源应用」

`来源 · 应用 · 时间 · 大小[ · 尺寸] · 类型`，来源写平台名（**Mac / Windows**，
不再是「本机/对端」）。应用名来自 poll 时抓的前台应用；有 bundle id 就在名字前画
13px 应用图标（`ui/mac2/apps.py`），取不到（如「截图」）就只写文字。

### 10.7 预览气泡：箭头与布局

- 箭头**必须做成子控件**：父级 `paintEvent` 先画、子控件后画，画在父级里会被圆角卡片
  整个盖掉 —— 这就是「箭头不见了」。三角 12×18，底边压在卡片边上。
- 高度 = 头 + 正文 + 底栏，**三块都钉死**：底栏被压就会裁掉按钮（「按钮贴边」）；
  正文按实际宽度量高；超出分类上限只压正文，不压头尾。
- 图片**只缩不放**（`QPixmap.scaled` 的 KeepAspectRatio 会放大），并按剩余高度换算。


### 10.8 窗口用系统标题栏（可拖动）

去掉了自绘工具条之后，不再开 `NSWindowStyleMaskFullSizeContentView`：内容铺到标题栏
底下会吃掉拖拽区域，窗口就拖不动了（2026-10-21 实测）。现在标题栏归系统，侧栏从
标题栏下沿开始。

### 10.9 菜单栏：单击弹菜单、双击开主界面

| 操作 | 行为 |
|---|---|
| 单击 | 弹菜单（延迟 240ms，避开双击） |
| 双击 | 打开主界面并置前 |

强制切 / 剪贴板 / 设置 / 退出；状态行前面加**状态灯**（本机绿、另一台/未知灰）。
NSMenu 是系统画的，毛玻璃/hover 蓝条/键帽这些由系统决定，不自绘（自绘菜单要另开

### 10.13 悬浮预览：鼠标移出气泡即关

原来只有「离开缩略图」才计时关闭，从缩略图直接移到窗外会挂着。现在气泡 `leaveEvent`
也走 220ms 关闭（移回缩略图会取消）。

### 10.14 设置页：去掉外观与保留历史，存储上限可改

| 项 | 结果 |
|---|---|
| 外观 | 整行删除；appearance 固定 `light`（用户不要深色模式） |
| 保留历史 | 整行删除（引擎仍按 30 天兜底清理） |
| 存储上限 | 可手动输入（10–5000 MB）+ 旁边「清理」按钮（走清空确认），左侧显示「已用 X MB」；超过上限自动丢弃最旧的记录 |

数值框用 QLineEdit 而不是 QSpinBox：QSpinBox 一旦被 QSS 改边框，内部输入框宽度会被算成
1px，文字完全看不见（实测）。QSS 给 QLineEdit 加 padding 没问题。

### 10.15 访达复制图片：优先用文件预览，别用 Finder 的图标位图

Finder 复制图片时粘贴板里同时有 `public.file-url` 和一张**文件图标**的位图。之前先读
位图，于是列表里是一张空白 PNG（就是「复制图片给我 PNG 空白」）。现在：

- 有 `public.file-url` → 先判断扩展名；是图片就读文件生成预览（≤1600px），**忽略**位图；
- 是普通文件 → 不用图标位图，按文本（路径）处理（文件本身不跨端同步，契约 P2）；
- 没有 file-url（截图、网页图片）→ 才用粘贴板里的 PNG/TIFF。

### 10.16 文件：分「截图 / 图片文件 / 普通文件」三类

按 Frset 的实测行为（2026-10-21 用户贴图对照）落定：

| 类型 | 缩略图 | 标题 | 元信息 |
|---|---|---|---|
| 截图（粘贴板里的 PNG/TIFF，无文件） | 截图本身 | `图片 W×H` | `Mac · 截图 · 时间 · 大小 · 尺寸 · 图片` |
| 图片文件（访达复制） | **图片内容**（读文件抽的预览图） | **文件名** | `Mac · 访达 · 时间 · 目录` |
| 普通文件（访达复制） | **文件瓷砖**（文档字形按扩展名分派） | **文件名** | `Mac · 访达 · 时间 · 目录` |

- 判定：`ClipRecord.path` 非空 = 文件（`classify_record` 里 **path 优先**），
  图片文件也是「文件」，不是「图片」。
- 目录家目录缩成 `~`（`short_dir`），跟访达/终端一致；文件名过长按两行折行。
- 缩略图字形按扩展名分派（Lucide）：图片 → `file-image`、压缩/安装包 → `file-archive`、
  其它 → `file`。
- **文件不跨端**（契约 P2）：只在本机留一条「仅本机」；图片文件的图片内容照常按图片同步。

### 10.17 预览窗的文件卡

图片文件也走**文件卡**（缩略图里已经能看到图了，卡片只回答「这是哪个文件」）：

```
[文档图标 + PNG]        ← 52px 字形，下面印扩展名（Frset 同款）
同景不同高度：湖畔….png   ← 文件名，12px/650，居中，最多两行
~/Downloads/照片         ← 目录，10px，居中
─────────── 底栏 ───────────
3.0 MB · 14:33    [预览][打开文件][复制]
```

头部标题写「文件」，不重复文件名。底栏左侧显示 `大小 · 时刻`。

### 10.19 单击行 = 直接复制

- **双击行 → 预览**（以前是单击预览、双击复制，反过来了）。
- 悬停缩略图 450ms 仍照旧弹预览，不占单击。

### 10.20 文本预览：**完整显示**，只有超屏才滚动

预览是「看内容」，不是摘要 —— **不许截断**（用户 2026-10-21 明确否掉了上一版的截断）。

| 文本长度 | 表现 |
|---|---|
| 一两行 | 气泡就长那么高（如 210×145） |
| 几十行 | 气泡跟着长高（**可以超过旧上限 270**），不出现滚动条 |
| 长到超过屏幕 | 气泡长到屏幕高度（屏幕可用高 −120），**正文内部滚动**，内容一个字不少 |
| 极端大（> `PV_TEXT_MAX_CHARS` = 2 万字） | 才限制渲染量，正文末尾写清「只渲染了前 2 万字 / 共 N 字；复制仍是全文」 |

实现要点：

- 正文放进 `QScrollArea`（无边框、透明底），QLabel 高度按**实际换行量**量出来，
  所以「无滚动条」时滚动区高度正好等于文字高度；
- 出现滚动条时给滚动条让出 7px 再量一次，避免文字被压到滚动条下面；
- 滚动条 handle 用 `ink3`（默认的 `line` 在白底上等于看不见）；
- 高度上限 = `min(分类上限, 屏幕可用高 − 120)`，绝不超出屏幕。

### 10.21 重复复制不去重堆行

按内容指纹（`ClipItem.digest`：文本 + html + 图片 + 文件路径）去重：

- 同一条内容再复制 → **不新增行**，把原行**提到最前**并刷新时间；
- 文件按「路径」参与指纹，所以不同目录的同名文件是两条。

### 10.22 访达的文件引用 URL

访达有时给的不是普通路径，而是 `file:///.file/id=6571367.29…`（文件引用 URL / inode 引用）。
直接 `urlparse` 会得到 `/.file/id=…`：标题变成 `id=6571367.29202959`、目录变成 `/.file`、
点「打开文件」也打不开。

后端统一过 **NSURL**：`isFileReferenceURL()` → `filePathURL()` 解析成真实路径；
解析出来但文件已经不存在的，按普通文本处理（不再生成打不开的文件卡）。

### 10.23 图片预览尺寸：改成 Frset 的 clamp 模型（2026-10-23）

逆向实测 Frset（原生 SwiftUI、NSPopover），尺寸是**硬钳制**而不是单一上限：

```
窗口宽 = clamp(内容宽 + 水平 chrome, 346, 562)
窗口高 = clamp(内容高 + 垂直 chrome, 226, 626)      内容框 ≈ 524×524
```

七组实测（1460×900 屏）：1560×1216→562×512、2940×1696→562×406、8:1 超宽→562×226、
800×800→562×626、350×1200→346×626、250×2000→346×626、100×75→346×226。

我们照这个模型改，但 chrome 是自家的（头 39 + 底栏 48 + 正文内边距 28）：

- 窗口 346×226 ~ **562×626**，内容框 **522×509**（比原来的 372×181 高一倍多）
- 下限只给图片：小图不放大（糊），但气泡不塌成一条，图居中留白
- 竖图被高度封顶后宽度落在下限 346，不再缩成一条细缝
- 翻到右侧时会夹进屏幕（窗口变宽后更容易顶出右缘）
- 文/码/文件卡的上限不动 —— 它们本来就该贴着内容走

**第二轮（同日）**：删掉图片正文里的注脚行「1560×1216 · 2.3MB」。
尺寸在标题栏（`图片 1560×1216`）和底栏（`… · 2.3MB · 1560×1216`）各有一遍，
正文再摆一遍纯属重复，还白吃 32px 高度。删掉后内容框 522×477 → **522×509**，
与 Frset 的 524×524 只差 2×15（剩余差距来自 chrome 口径：Frset 102 / 我们 117）。

守卫：`tests/test_ui_mac2.py::test_preview_image_clamps_to_bounds`。

## 12. 配对电脑（2026-10-22 新增 · 已实现）

> 原型：`design/redesign/index-v2.html` → 侧栏「配对电脑」页 / 控制条「配对」分段（7 个状态）。

**评审拍板的 4 个决定（已按此实现）**：

1. **主流程**用「一端显示 6 位码、另一端输入」，不再要求两端各敲一遍同一个码；
2. **一对一**：再配一台 = 替换现有设备，必须二次确认（不做多设备列表）；
3. **两个入口共存**：侧栏「系统 → 配对电脑」是主入口；菜单栏弹出菜单保留「配对电脑…」快捷入口；点击都进同一页，不再放设置行；
4. **`clipboard.peer` 降级为可选提示**，设备发现常开 —— 这是「换一台电脑也能用、换 IP 不用改配置」的关键。

### 12.1 为什么必须做

现状（`CLIPBOARD-SYNC-CONTRACT.md` §4.4 / `cli.py` 的 `clip pair`）：

- 配对只能命令行：两端各执行 `dualswitch clip pair --pin 123456`，还得手动保证是同一个码；
- `clipboard.peer` 可能是手填 IP，换 Wi-Fi / DHCP 换地址后要重新改配置；
- 界面上只有「已配对 / 未配对」的结果，**没有任何入口能完成配对**。

结论：目前是两个开发机之间的调试路径，不是产品路径。要做成产品，缺的不是加密强度，
而是「**发现另一台 → 一次确认 → 永久记住**」这条最短路径。

### 12.2 目标 / 非目标

| | 内容 |
|---|---|
| 目标 | 同一个局域网内，普通用户不看文档也能在 30 秒内完成配对；配对一次后换网络/重启/IP 变化都不再操作 |
| 目标 | 配对过程不把 6 位码发到网络上；只允许一次成功，5 分钟过期，最多 5 次尝试 |
| 目标 | 已配对 / 未配对 / 密钥不匹配三种状态在侧栏导航项与配对页说法一致 |
| 非目标 | 多设备同时配对（契约只支持「另一台」；再配 = 替换） |
| 非目标 | 公网 / 中继 / 账号体系（仍只做局域网） |
| 非目标 | 在配对阶段改变加密算法（继续用现有 PBKDF2 + HMAC 帧加密） |

### 12.3 入口：侧栏导航（主）+ 菜单栏（快捷）

配对页是侧栏里的一个**独立导航页**，与切换 / 剪贴板 / 设置同级；菜单栏弹出菜单保留一个快捷入口：

| 入口 | 位置 | 右侧状态 | 行为 |
|---|---|---|---|
| **主入口** | 侧栏「系统 → 配对电脑」 | **状态灯**：绿=已配对、灰=未配对、红=需重新配对；悬浮显示文字；收起时缩到图标右上角（§0.4） | 点击进入配对页（未配对=附近设备，已配对=管理） |
| **快捷入口** | 菜单栏弹出菜单「配对电脑…」 | 文字（未配对 / 已配对 / 需重新配对） | 点击进入**同一个**配对页（调用同一个 `openPair()`） |

- 侧栏位置：「系统」分组，放在「设置」上方。
- 配对页是独立页面，不是设置页的钻取页，也不是弹窗；**页内不放返回按钮**，切页靠侧栏。
- 两个入口的状态含义必须一致：侧栏是状态灯（悬浮显示文字），菜单是同一段文字；
  菜单项文字固定「配对电脑…」。
- 剪贴板页、设置页、侧栏 footer 都不再放第三个配对入口。
- 未配对时剪贴板行「仅本机」药丸点击 → toast「还没有配对，去左侧栏「配对电脑」」。

> 单窗口铁律不变：配对页是主窗口 `QStackedWidget` 里的一页，和切换/剪贴板/设置平级；菜单项只是快捷跳转。

### 12.6 底层怎么做（复用现有 HELLO 认证，不新增帧类型）

契约 §4.4 的原始设计本来就是「A 显示 PIN、B 输入 PIN」，实现后来为了 CLI 方便改成了
「两端输入同一个 PIN」。这次把**原始的挑战应答流程**补回来，协议不用加新帧：

1. **A 显示码**：`key = PBKDF2(PIN, PAIR_SALT)`（现有 `derive_key`，固定盐正好支持单边输入）。
   A 把 `key` 作为**临时待配对密钥**交给 transport（不写 config），关闭旧连接，重新监听；
   状态记 `pairing_wait`，5 分钟有效。
2. **B 输入码**：同样算出 `key`，连 A 的 47823，HELLO 里带 `auth = HMAC(key, nonce)`。
   A 用临时 key 校验（现有 `verify_hello` 已经这么做了），通过后回 `HELLO_OK(ok=true)`；
   B 用 key 校验 A 的 HELLO。双向认证通过 = 双方都证明知道这个 PIN。
3. **落盘**：两端在 `transport.authenticated == true` 后写
   `clipboard.psk = key.hex()`、`clipboard.peer_device`、`clipboard.peer_name`、`clipboard.paired_at`；
   A 的临时 key 转正，`pairing_wait` 结束。**PIN 本身从不上网**。
4. **失败/取消/超时**：A 丢弃临时 key，恢复原 key（未配对则为空）；B 丢弃临时 key，
   回 `未配对`。任何一侧都不保存。

需要的引擎接口（实现时）：

```python
engine.begin_pairing()            # 生成 PIN + pending key，返回 PIN（界面显示）
engine.cancel_pairing()           # 丢弃 pending key，恢复原 key
engine.pair_with_peer(addr, pin)  # B 端：设临时 key，连 addr，等认证结果（超时 15s）
engine.unpair()                   # 清本机配对信息，停同步
engine.pairing_status()           # idle | showing | connecting | paired | failed(reason)
```

`Transport` 只加一个 `set_key(key, *, drop_links=True)`：更新 `self.key`；已有连接按「主动断开」
关闭，让拨号/监听线程用新 key 重新握手。现有 `Link` 在创建时读 `self.key`，不需要改帧格式。

**配对后的身份绑定**：`transport` 记住 `peer_device`，之后只接受 HELLO 里 `device` 等于它的连接；
别的设备即使拿到同一个 key，也回 `HELLO_OK(ok=false, reason="已与另一台设备配对")` 并断开。
解除配对时一起清掉 `peer_device`。

**兼容性**：

- 已有 `psk` 的旧配置（CLI 配对）继续可用；配对页显示「已配对（旧版配置）」，给「重新配对」按钮。
- CLI `dualswitch clip pair --pin` 保留，作为无界面/排障路径；语义仍是两端同一个码。
- 旧版本客户端收到同样的 HELLO 只会认为「未配对」，不会崩；升级后重新配对即可。

### 12.7 设备发现（`sync/discovery.py` 增量）

现有广播只有 `{ds, v, device, host, port, ts}`。页面要显示平台和配对状态，建议补四个可选字段
（旧实现忽略即可）：

| 字段 | 值 | 用途 |
|---|---|---|
| `plat` | `"macos"` / `"windows"` | 列表行左侧平台牌 + 标签 |
| `ver` | 应用版本，如 `"0.4.2"` | 版本不一致时给提示，不阻断 |
| `pairing` | `true/false` | A 显示配对码期间为 true，B 列表显示「正在等待配对」 |
| `paired` | `true/false` | 对端是否已有配对对象，用于「替换配对」文案 |

- `host` 改成**电脑名**（macOS `ComputerName`、Windows `COMPUTERNAME`），取不到再回落
  `device_id`；现在配置里的 `mac` / `windows` 只适合开发机。
- **`clipboard.peer` 降级为「可选提示」，不再关闭发现**：现在 `_build_transport` 里
  `if peer is None` 才启动 Discovery，等于手填一次 IP 就永久依赖那个地址。改成：
  发现始终启动；手填地址只用于「立即先拨一次」，发现到对端后以广播结果为准；
  配对成功后可清空该提示（不影响已经保存的配对）。
- 发现只用于「告诉你对端在哪」，不参与认证；数据仍只走认证后的 TCP。
- 广播失败（企业 Wi-Fi）时，手动 IP 是唯一兜底；手动 IP 仍需 A 显示配对码。

### 12.8 边界与异常

| 场景 | 表现 |
|---|---|
| 两端都没点「显示配对码」 | 对端广播里 `pairing` 不为 true 时，点「配对」先给行内提示「请先在另一台电脑上点『显示配对码』」；仍可进入输码（老版本没有该字段），失败后提示「对方不在配对状态」 |
| 输错 1–4 次 | 行内红条 + 剩余次数，输入框保留，允许继续 |
| 输错第 5 次 | 行内红条「配对码已失效」，清空并禁用输入；A 端码同时作废 |
| 码过期 | A 自动回发现页；B 提交时提示「配对码已过期，请让对方重新显示」 |
| 配对中途切页/关窗 | 取消，不落盘；A 的码立即失效 |
| 对端已被别的电脑配对 | 列表显示「已与别的电脑配对」；点「替换配对」先确认「对方会断开现有配对」 |
| 本机已配对再配另一台 | 状态 6 → 重新配对时确认「将替换现有设备」；成功后旧配对信息被覆盖 |
| 两端版本不一致 | 握手成功但功能字段缺失时提示「对端版本较旧，建议两端一起升级」；不阻断文字同步 |
| 防火墙拦截 | 状态 7，文案明确给出地址和「检查防火墙」，不是静默失败 |
| 配对后换 Wi-Fi / IP 变化 | 已配对状态不变；UDP 重新发现或手填 IP 后自动连上 |
| 睡眠唤醒 | 3s 内自动重连；配对状态不受影响 |
| 密钥不匹配（两端 psk 不同） | 侧栏「配对电脑」右侧显示「需重新配对」，配对页给红条提示，点进去直接到状态 1，而不是「未配对」 |
| 配对码显示期间 App 退出 | 无残留：临时 key 只在内存，config 不写 |

### 12.12 验收清单（已逐项自测）

1. 两台从未配对的电脑：A 显示码，B 在附近列表选中 A 并输码 → 两端 5s 内变「已配对」，复制中文/图片互通。
2. 输错 4 次仍可继续；第 5 次后码失效，A 端同时作废。
3. 配对码等满 5 分钟 → 自动失效，B 提交得到「已过期」。

9. 两端都打开配对页但没人显示码 → 点「配对」给明确提示，不进入等待。
10. 侧栏「配对电脑」右侧状态灯与配对页一致（灰=未配对、绿=已配对、红=需重新配对），
    悬浮在灯上能显示对应文字；未配对时「仅本机」药丸点击给引导文案。

## 13. 退出应用按钮（2026-10-22 新增 · 已实现）

### 13.1 问题

现在窗口里没有退出出口：要么右键菜单栏图标，要么打开菜单点「退出 屏幕切换」。
用户不知道菜单栏图标还能右键，也不一定记得 `⌘Q`。窗口需要一个看得见、随时可按的退出动作。

### 13.2 位置：侧栏底部，状态行下方

```
┌──────────────────┐
│ 核心              │
│ ⇄ 切换            │
│ ▤ 剪贴板          12│
│ 系统              │
│ 配对电脑          ● │
│ ⚙ 设置            │
│                  │
│                  │
│ ● 已连接 Windows   │
│ 热键 [⌥] [Space]   │
│ ───────────────  │
│ ⏻ 退出应用         │
└──────────────────┘
```

- **底部状态栏已删除**（2026-10-22 用户要求）：对端连接状态回到侧栏 footer，
  版本号不再显示；窗口底边不再有 30px 横条。
- **热键用键帽**：`热键` 标签 10px / `ink-3`，右侧沿用 §0.3 的键帽组件
  （18px 高、`card-3` 底、1px `line` 描边），不改大块键帽的观感；
  热键未启用时写「热键未启用」并用 `warn` 色。
- **对齐规范（8px 栅格）**：侧栏内边距 10 + 行内边距 10，
  再按 `[16px 引导列][8px 间距][文字列]` 排 —— 状态灯和电源图标都居中在
  16px 引导列里，三行文字统一从侧栏左边缘 44px 处开始。
  行内边距画在状态行 / 热键行 / 退出按钮**内部**（footer 布局本身左 0），
  这样退出按钮可以铺满整行、粉底从侧栏内沿开始，图标离粉底还有 10px。
- **退出按钮 hover**：只加 `#FEF2F2` 淡红底；图标和文字保持 `ink-3`，不变红。
- **分隔与间距**：footer 上内边距 10 / 下 2；分隔线上下 9 / 7；
  退出按钮 31px 高，距分隔线 1px（与原先一致）。
- **侧栏收起时**：状态行 / 热键行 / 分隔线隐藏，只留居中的电源图标，
  tooltip 仍是「退出应用（⌘Q）」（§0.4）。
- **不放标题栏**：系统标题栏保持无工具钮（§10.1 / §10.8）。
- **不放设置页**：退出是全局动作，切到任何页都应该能按。
- **不占导航项**：它是 footer 动作，不是第四个功能页；不参与侧栏高亮。
- 位置固定，不随页面切换隐藏。

### 13.3 行为

| 项 | 规格 |
|---|---|
| 点击 | **直接退出，无二次确认**（用户 2026-10-22 明确要求） |
| 退出范围 | 整个应用：先停同步引擎、停全局热键、移除菜单栏图标/托盘、关窗口、退出进程 |
| 「关闭窗口后仍在菜单栏运行」 | 该开关只影响关窗口；本按钮**始终完全退出** |
| 与菜单「退出 屏幕切换 ⌘Q」 | 复用**同一个处理函数**，行为完全一致，不允许两条退出路径各写一套 |
| 键盘 | 保留 `⌘Q`；按钮 tooltip「退出应用（⌘Q）」 |
| 配对 / 传输中 | 仍可退出；配对临时密钥只在内存，退出即失效，不落盘 |
| 二次确认 | 无；靠位置隔离（底部单独一行）+ hover 危险色降低误点 |

### 13.4 视觉规格

| 项 | 值 |
|---|---|
| 对齐 | 8px 栅格：侧栏 10 + 行内 10 + 16px 引导列 + 8px 间距；三行文字统一起于 44px |
