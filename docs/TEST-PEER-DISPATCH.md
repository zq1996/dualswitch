## 第 1 步：屏幕在 Windows → 在 Mac 上点（修的就是这一半）

**当前状态**：屏显示 Windows 桌面。

**操作**：在 Mac 上打开「屏幕切换」主窗口，点那个蓝色主按钮
（文案应该是「**切换到 Mac**」）。

**应该看到**：
1. 按钮立刻变忙、下面提示「正在发送 DDC Set · 目标 Mac」；
2. **2–3 秒后屏切到 Mac**（这是显示器的切换耗时，不是卡住）；
3. Mac 上提示成功，Hero 卡变成「当前画面 Mac」。

**Mac 日志**（`~/Library/Application Support/dualswitch/logs/dualswitch.log`）：

```bash
grep -aE "远端代发|画面不在本机|活动显示器" dualswitch.log | tail -20
```

应该出现 `远端代发切屏 → ok`。

**Windows 日志**（`%APPDATA%\dualswitch\logs\dualswitch.log`）：

```bash
grep -a "替对端切屏" dualswitch.log | tail -5
```

应该出现 `替对端切屏 VCP 0x60=18 → ok`。**这条以前一次都没出现过。**

## 出问题时给我这些

**先看启动日志里的这一行**（`cmd_ui2` 每次启动都打，三路证据并排）：

```
归属判据：活动屏=…；DDC 枚举=…；对端上报=…；界面判定=…
```

- `活动屏=<空>` + `DDC 枚举=AOC…` = 判据正确（屏挂着但不在用）；
- `活动屏=AOC…` = **`CGDisplayIsActive` 也认为屏在本机**，说明这块屏在 HDMI
  输入下仍保持着 USB-C 链路 —— 那就得换判据，把这行发我；
- `对端上报=None` = 链路还没通 / 对端旧版本。

| 现象 | 需要的证据 |
|---|---|
| 点了完全没反应 | Mac 日志里 `grep -aE "远端代发|切换失败|画面不在本机"` 的全部输出 |
| 报「画面不在本机，请对端代发失败」 | 同上 + Windows 端 `grep -a "替对端切屏"` |
| 屏切过去 2–3 秒又回来（回弹） | 手机录屏 + 两端日志（这是**另一个**问题，见 INVESTIGATION 第 4 节） |
| 报「未检测到外接显示器」 | Mac 上 `dualswitch probe` 的完整输出 |
| 界面首帧判错 | 启动日志的 `归属判据：…` 那一行 |
