# V3 升版方案（与 V2 并存）

> 2026-11-07 立。回答「能不能升版、V2 会不会被弄坏、V3 怎么跟 V2 共存」。
> **结论：能，而且 V2 已经是个冻结的二进制，改源码动不到它。但有三条隔离线不做，V2 一定会被弄坏。**

---

## 1. 一句话方案

```
git worktree  →  ../dualswitch-v3  （v3 分支）
配置目录      →  Application Support/dualswitch-v3/    ← 必须隔离（最关键）
同步端口      →  47833 / 47834（V2 用 47823/47824）   ← 必须隔离
App 名        →  「屏幕切换 V3」/ com.dualswitch.app.v3
```

V2 继续用 `/Applications/屏幕切换.app`（已打包，**不会因为你改源码而改变**）；V3 从源码跑或打成独立的「屏幕切换 V3.app」，两者互不干扰。

---

## 2. 为什么 V2 是安全的（先消除这个顾虑）

你现在用的是**已打包安装的 `.app`**，它是一份冻结的二进制，里面自带一份 Python 和全部代码。
你改仓库里的 `src/` 对它**没有任何影响**——它读的是自己包内的代码，不是仓库。

所以「升版把 V2 弄坏」这件事，唯一的途径是**它们共用同一份 config.json**。
2026-11-06 那次事故就是这个：新版改了配置结构 → 写回默认值 → 旧版（和旧二进制）读不懂 → 设置全丢。

---

## 3. 三条隔离线（缺一不可）

| 隔离项 | 现状 | V3 要改成 | 不做的后果 |
|---|---|---|---|
| **配置目录** | `~/Library/Application Support/dualswitch/` | `…/dualswitch-v3/` | ★**V2 的配置会被 V3 覆盖**，就是 11-06 事故 |
| **同步端口** | TCP 47823 / UDP 47824 | 47833 / 47834 | 两个版本在同一台机都跑时互相发现、抢连接、剪贴板串台 |
| **App 名 / bundle id** | 「屏幕切换」/ `com.dualswitch.app` | 「屏幕切换 V3」/ `com.dualswitch.app.v3` | 装 V3 会覆盖 V2 的 app；TCC（辅助功能/屏幕录制）授权串位 |

好消息：**前两条不用大改代码**——
- `config.py` 已经有 `DUALSWITCH_CONFIG` / `DUALSWITCH_LOG` 环境变量覆盖（`config_path()`、`log_path()`）；
- 配置目录由 `APP_NAME` 决定，V3 分支里改一个字就行；
- 端口在配置的默认值里（`clipboard.port` / `discover_port`），改默认值即可。

但打包成 app 后环境变量传不进去（Finder 启动不带），所以**还是要在 V3 分支里把 `APP_NAME` 改成 `dualswitch-v3`**，别指望环境变量。

---

## 4. 为什么不建议「把代码复制一份到 V3 目录」

能跑，但代价大：

1. **共享层会变成两份**（`sync/`、`clipboard/`、`config.py`）。你和 Windows 端是按「共享层只有 mac 端一个作者」协作的，两份副本之后任何契约变更都要改两次，而且很容易漏。
2. 两份目录**没有共同的 git 历史**，以后想把 V3 的修复拿回 V2 就只能手动抄。
3. 两端并行开发时最容易出问题的就是「以为改的是同一份代码」。

**推荐 `git worktree`**：同一个仓库，两个检出目录，两个分支，共享历史，随时能 merge / 回退。

```bash
git branch v3
git worktree add ../dualswitch-v3 v3
```

之后：`/Users/zhqi/work/workbuddy/dualswitch` = V2（main，只修紧急 bug），`../dualswitch-v3` = V3（新功能）。
目录里各自建 `.venv`（`tools/py.sh` 按仓库定位，不会串）。

> 如果你更习惯「一个目录切分支」，也行——只要别在 main 上直接开 V3 的工。但切分支时源码版 V2 会暂时不可用（打包版不受影响）。

## 5. 代码层的落地方式

| 项 | 做法 |
|---|---|
| 入口 | 新增 `ui3` 子命令 → `ui/mac3/runner.py`（沿 `ui`/`ui2` 并存先例，v1/v2 都不动） |
| 配置目录 | `config.py` 的 `APP_NAME` 在 v3 分支改为 `dualswitch-v3` |
| 端口默认 | `clipboard.port` 47833、`discover_port` 47834 |
| 打包 | `packaging/macos/build.sh` 的 `APP` 改 `dist/dualswitch-v3.app`，PlistBuddy 补「屏幕切换 V3」，bundle id 加 `.v3` |
| 首次启动迁移 | V3 第一次跑时**只读**读一份 V2 的 config（拷贝到自己的目录后再改），绝不回写 V2 的文件 |

⚠️ **V2 与 V3 不能互通**：端口不同就发现不了对方。两端要升一起升；如果必须混用，V3 得同时监听旧端口（不推荐，会把「互相抢连接」的风险带回来）。

## 6. 页面调整（按你的意见改）

### 6.0 边界：未改动的部分一律保持原样

设计稿按 `ui/mac2/theme.py` 的 **QSS 实测值**重画，不是重新设计：

| 元素 | 实际值（不得改动） |
|---|---|
| 一行动作 | 高 58、左右 padding 12、间距 10 |
| 数字章 | 36×26、`card3` 底、1px `line`、圆角 7、12.5px/700 |
| 文字列 | 端口名 12px/650 `ink2` + 归属 10px `ink3` |
| **主按钮** | **150×38、accent 实底白字、圆角 10、13.5px/650、15px 显示器图标、文案「本机发送 N」** |
| **兜底钮** | **28×28、白底 1px `line`、圆角 8、13px 纸飞机图标（无文字）** |
| hero | `card2` 底、62×62 图标板、名字 26–27px/700 |
| 侧栏选中 | accent **实心**底 + 白字（不是左侧竖条） |
| 设置行 | 高 ≥50、padding 15/12、标题 12.5/550 + 副行 10.5 `ink3` + 右侧等宽值 |

> 之前的草图把「主按钮 + 纸飞机小钮」错画成两个文字按钮，已按真实实现改正。

### 6.1 两条采纳的意见

1. **标定不放进左侧菜单** ✅
   启动时检测不到「当前屏的 profile」→ **自动弹独立初始化窗口**（无侧栏，「准备 → 逐口切 → 确认」三步，可「稍后再说」，不阻断切屏）。
2. **设置页承担重新读与接线** ✅
   设置页「显示器」区新增一行「显示器配置 ›」，点进去是**同一窗口内的子页**（左侧栏仍高亮「设置」），**不是新开窗口/弹窗**。

### 6.2 显示器配置子页

顶部「‹ 返回设置」，内容四块：

1. **当前显示器**：型号 + 厂商/产品号/序列号 + 标定状态 + `重新识别` / `重新标定`
2. **接线**：两个下拉（这台 / 对方）+「保存后立即生效」
3. **端口码表**：端口名 + 当前用途（对方正在使用 / 空闲）+ 可编辑数值
4. **已保存的显示器**：**可展开/收起**。收起显示「型号 · 分辨率 · 端口数 · 标定时间」，展开显示该屏端口码 + `设为当前` / `删除`；内置「默认配置（未识别的屏）」不可删。

### 6.3 双 Windows 的身份标识（三个正交维度）

| 维度 | 用在哪 | 双 Windows 时 |
|---|---|---|
| **角色色**：本机蓝 `#4E87FF` / 对方紫 `#7C5CFF` | 圆点、徽章、角标底 | ✅ 固定，一眼分开 |
| **机器名**（`DESKTOP-A1B2C3`） | 端口行第二行、剪贴板 meta | ✅ 天然不同 |
| **平台图标/小字** | 徽章内、角标图标 | ⚠️ 会一样，只表示平台 |

**首字母不承担区分职责**，只是徽章里的视觉锚点。真正区分靠「角色色 + 完整机器名」；两台都 `D` 开头也没关系（`DESKTOP-A1B2C3` vs `DESKTOP-X9Y8Z7`）。

### 6.4 剪贴板角标规则

现状：缩略图右下角 22×22 角标，`Mac = 灰底白苹果` / `Win = 蓝底白四格`；双 Windows 时两条全蓝，分不出来。

改后只用一条规则：

- **本机记录**：保持系统原色（Mac 灰底苹果 / Windows 蓝底四格）
- **对方记录**：一律 **紫底**，图标仍是对方的系统图标

于是 Mac+Win → 灰苹果 / 紫四格；**Win+Win → 蓝四格 / 紫四格** ✅；Mac+Mac → 灰苹果 / 紫苹果 ✅。

### 6.5 标定结果可手工改

读通道成功率只有 50%，可能抓到上一口的残留值。确认页与设置页码表都允许直接编辑，并提供「手工填码」兜底。

### 6.6 标定流程必须「自动切回」（2026-11-07 用户指出，本方案的关键）

**死结**：切到目标口之后，画面就不在本机了，引导窗口看不见 → 用户不知道下一步该切哪个口。

**解法**：标定开始时先读一次，记住**起始口**（用户此刻所在的口，如 USB-C = 100）。之后每一步：

1. 提示「请切到 HDMI 1」
2. 轮询读 `0x60`；值变化且连续 2 次稳定（间隔 0.4s）→ 记为该口的码
3. **立刻发 Set 切回起始口的值**（读一次之后的下一条写会被吞，所以要连发两条，见 `MONITOR-PROFILE.md` §3）
4. 等 2–3 秒（显示器切换本身的耗时），画面回到本机
5. 界面从「正在切回」切到「请切到 HDMI 2」，进入下一轮

规则：
- 用户切回的正是起始口时，跳过第 3 步；
- **起始口本身不需要标定**（值已知），最后一步直接跳过；
- 全程必须显示「正在切回 · 画面马上回来」，否则用户会以为卡死；
- 连续 N 次读不到（切到了没接设备的空口）→ 提示「这个口没信号」，给「跳过 / 重试」两个按钮；
- 每步的码值都要能手工改（§6.5）。

### 6.7 图标与视觉资源：沿用现有的，不自绘

| 类型 | 做法 |
|---|---|
| **原有图标**（显示器、纸飞机、苹果、Windows 四格、侧栏四个） | **一律不动**，实现时从 `ui/mac2/icons.py` 取（`icons.svg_pixmap(...)`） |
| 设计稿里的图标 | **仅示意，不作为实现依据**；不要照着设计稿重画 |
| 需要新增的图标 | 从 **Lucide（ISC）/ Simple Icons（CC0）** 取，走 `tools/gen_iconlib.py` 重新生成 —— 与项目既有规范一致，**不自绘 SVG** |
| 纯色调整（如剪贴板角标改紫） | 允许，只换底色，不新画形状 |

> 设计稿里手绘的纸飞机、苹果等形状确实不够准，**实现时不要用**，以 `icons.py` 为准。

### 6.8 显示器配置页：一屏内，不滚动

初版做成纵向列表，内容一多就要滚，体验差。改为紧凑布局，实测 **570 高正好放下**：

- 显示器信息压成**一张卡的一行**（44×44 图标 + 名称/身份 + 右侧两个按钮）
- **接线**用两张并排小卡（这台 / 对方），不占整行
- **端口码表**用 **2×2 格子**（端口名 + 大号码值），而不是 4 个列表行
- **已保存的显示器**默认收起，只留标题行；展开才出现码值和操作

## 7. 双 Windows 怎么区分（页面层面）

原来靠「Windows / Mac」两个词区分，双 Windows 就废了。改成**三个正交标识**，任何一个平台组合都能区分：

| 维度 | 用在 | 双 Windows 时 |
|---|---|---|
| **机器名**（`DESKTOP-V6DVLD8`） | 角标主文案 | ✅ 天然不同 |
| **标识色 + 首字母徽章** | 圆形徽章（本机=蓝、对方=紫） | ✅ 一眼分开 |
| **平台图标** | 徽章右下角小角标 | ⚠️ 会一样，但只用来表示平台 |

也就是：**名字区分身份，颜色区分角色，图标只表示平台**。三个一起用，Mac+Win 和 Win+Win 都不会认错。

## 8. 还缺什么（你问的「这样还缺什么吗」）

| # | 缺口 | 为什么必须有 |
|---|---|---|
| G1 | **标定中画面会离开本机** | 切到别的输入口时 Mac 就没画面了，教程必须提前说明「切回来才算完成」，否则用户以为卡死 |
| G2 | **标定结果二次确认** | 读成功率 50%，可能抓到上一口的残留值 → 确认页要能手工改 |
| G3 | **跳过/失败的降级** | 用户跳过某个口 → profile 缺该项，端口行要显示「未标定」但仍可点（发默认值） |
| G4 | **多块外接屏选哪块** | `active_monitor: auto` 的规则要定：按「当前在扫画面的那块」还是「上次用的那块」 |
| G5 | **同型号两台屏** | 主键 `mfg:pid` 会撞，需要 `AlphanumericSerialNumber` 兜底 |
| G6 | **换屏后不重启能否感知** | 现在是启动时读一次；换屏/热插拔要不要触发重新识别？（建议：切到切换页时刷新一次） |
| G7 | **V2↔V3 混版本** | 见 §5 的 ⚠️，要么一起升，要么 V3 双端口监听 |
| G8 | **Windows 端要有同样的引导** | 双端对称，否则 Windows 端用户没有标定入口 |
| G9 | **手工填码兜底** | 标定彻底失败时（读通道坏的屏），允许直接填数字 |
| G10 | **接线改了要立即生效** | 设置页改完 `wiring` 不能要求重启 |

以上 G1–G6、G9–G10 都是 P1/P2 必须覆盖的；G7 需要你定策略。

## 10. 开工前必须确认的一件事

**Windows 端能不能读到 `mfg:productCode`**（EDID 的 manufacturer ID + product code）。
mac 侧拿到的 `1507 / 9987` 就是这两个字段，Windows 从注册表
`HKLM\SYSTEM\CurrentControlSet\Enum\DISPLAY\<monitor>\<instance>\Device Parameters\EDID`
解析出来应该是同一对数字，但**没有实测过**。这条不成立，profile 主键就要换方案。
