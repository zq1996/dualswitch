# Windows 客户端界面设计（设计稿 v1）

> 2026-10-17 · 应用显示名 **屏幕切换**（包名 / CLI 仍是 `dualswitch`）
> 可交互稿：`design/windows/index.html`（浏览器直接打开，图标为真实 PNG）
> 图标：`design/icon/`（SVG 母版 + 10 档 PNG + 多尺寸 ICO）

---

## 1. 设计前提

| 约束 | 推导 |
|---|---|
| 99% 的时间用户看不见窗口 | 窗口不是主界面，托盘才是。窗口只在「确认状态 / 改配置」时打开 |
| 切换动作本身只花 65ms | 不做进度条、不做动画，做完就结束 |
| 切走之后本机就看不见了 | 「当前在哪台」必须一眼可读，不能靠猜 |
| 用户会按错方向（切到空口=黑屏） | 按钮文案必须写出**目标机名**，不写抽象的「切换」 |
| 这块屏的 VCP 值反常识（18 才是 USB-C） | 配置页就地解释，不能只放两个数字框 |

---

## 2. 信息架构

```
托盘图标（常驻）
├─ 左键双击 → 直接切换（单击不响应，防误触）
└─ 右键 → 菜单：切换 / 强制切到本机 / 探测 / 配置目录 / 日志 / 热键(只读) / 退出

主窗口 440×600
├─ 状态卡（当前主机 + 输入源 + 主按钮 + 上次结果）
├─ 设备卡 ×2（Windows 17 / Mac 18，可直接点）
├─ 排障列表（探测 / 日志 / 诊断）
└─ 状态栏（热键是否启用 + 版本）

设置窗口 440×600
├─ 常规：切换模式 / 通知 / 去抖
├─ 热键：录制 / 严格右 Alt / 吞键
├─ 显示器：匹配关键字 / 输入源映射
└─ 高级：后端、回读参数、打开配置文件
```

**只做两个窗口**：主窗口与设置。不做多文档、不做侧边栏导航——四个分页用顶部页签，一屏放得下。

## 3. 页面规格

### 3.1 主窗口

| 区域 | 高度 | 内容 | 交互 |
|---|---|---|---|
| 标题栏 | 44 | 图标 18 + 名称；右：最小化 / 关闭 | 关闭 = 收进托盘 |
| 状态卡 | ~200 | eyebrow「当前画面」+ 状态药丸；31px 主机名；`AOC Q2790PC · HDMI · 输入源 17`；主按钮；上次切换耗时 | 主按钮 = 切到对端 |
| 设备卡 | ~104 | 两台各一张：**Windows / Mac 官方图标** + 端口 + 输入源 + **指示灯（亮/灭）** | 点灭灯那张 = 直接切过去 |
| 排障列表 | 3×42 | 探测显示器（只读）/ 查看日志 / 运行诊断 | 打开对应 CLI 行为 |
| 状态栏 | 34 | 绿点 + 热键文案；右侧版本 | 静态 |

主按钮：`切换到 Mac` + 右侧键帽 `Alt` `Space`。
切换中：按钮禁用 + 文案换 `正在切换到 Mac…`，超过 200ms 才显示转圈（正常路径用户看不到）。

#### 设备卡的两态（亮灯 / 灭灯）

用显示器电源灯的逻辑表达「谁在用」，不读文字也能判断：

| 项 | 亮灯（使用中） | 灭灯（未使用） |
|---|---|---|
| 卡片底 | 品牌色浅渐变（Win `#F2F7FF` / Mac `#F1FBF9`） | 中性灰 `#F7F8FB` |
| 描边 | 品牌色 20% 透明 | `#E5E9F1` |
| 阴影 | 品牌色柔光 | 无 |
| OS 图标 | 官方原色（Win `#0078D4` / Apple `#11151C`） | `grayscale(1)` + `opacity .38` |
| 指示灯 | 品牌色径向渐变 + 外发光 + 3px 光晕环 | 灰色径向渐变 + 内阴影（凹进去） |
| 文字 | 主文字色，状态行用品牌色 | 全部降一档灰度，状态行最弱 |

不只靠颜色：去色 + 降透明 + 换底 + 文案变弱四件事同时做，色弱用户靠明度也能分辨。

### 3.2 设置窗口

页签 `常规 / 热键 / 显示器 / 高级`，每页 2–3 个分组，分组内一行一设置（标题 + 说明 + 控件）。

- 热键录制：点击后进入录制态，按下组合键即写入；非法值红框 + 行内提示，不弹模态。
- 输入源映射：`17 Windows` / `18 Mac` 两个数字框，说明文案必须带上「27 会被这块屏拒绝」。
- 保存：改完立即重建热键线程；DDC 后端变更提示「需重启」。

### 3.3 状态与异常

| 状态 | 呈现 | 是否打断 |
|---|---|---|
| 切换成功 | 状态卡更新 + 绿勾 + 耗时 | 否 |
| 切换中 | 按钮禁用 + 转圈（>200ms） | 否 |
| 切换失败 | 红色 banner（错误码 + 人话解释）+ 重试 / 查看日志 | 是（窗口内） |
| 回读未确认 | 托盘气泡「切换指令已发送」 | 是（一次性） |
| 热键被占用 | 黄色 banner + 改热键 / 忽略 | 是（窗口内） |
| 切走后回读失败 | **只写日志** | 否 |

## 5. 应用图标

> 采用用户提供的插画（两台显示器 + 双向弧形箭头），已抠成透明底并出齐全套尺寸。
> 上一版自绘图标归档在 `design/icon/_old/`。

### 5.1 语义

- **两台显示器（一深一亮）** = Windows / Mac 两端
- **首尾相接的两条弧形箭头** = 画面在两台机器之间来回换
- 与主窗口的两张设备卡形成呼应，比抽象箭头更直白

### 5.2 抠图（源图是白底 JPG，不是透明 PNG）

按**亮度 + 饱和度**双判据算 alpha，而不是按白色泛洪：

```
d = clamp((250 - L) / 30, 0, 1)   # 越白越接近 1
g = clamp(S / 16, 0, 1)           # 有颜色的像素接近 1
alpha = 1 - (1 - d) * (1 - g)
```

| 区域 | L / S | 结果 |
|---|---|---|
| 纯白背景 | ≈254 / 0 | 全透明 |
| 浅蓝机身 | ≈238 / 18 | 全不透明（被饱和度保住） |
| 柔和投影 | ≈235 / 3 | 半透明，阴影自然淡出 |
| 深色屏幕 | ≈40 | 全不透明 |

单纯按白色泛洪会把机身和箭头内部一起吃掉——这是第一版失败的原因，已记录在 `build_icon.py` 注释里。

### 5.3 尺寸策略

| 尺寸 | 处理 |
|---|---|
| 1024 母版 | 抠图后按内容边界裁正方形、居中，作为唯一母版 |
| 512 → 32 | Lanczos 降采样 |
| ≤128 | 追加一道 UnsharpMask(1.2 / 70% / 2) 抵消缩小的糊 |
| **16 / 20 / 24** | **改用简化版 `render_small()`**，不再缩母版 |

母版里两条浅蓝箭头在 16px 下只有 1px 宽、且接近纯白，缩下去是一团灰雾，反而把两块屏幕糊掉。所以 ≤24px 按图标设计惯例做减法：只留「两块屏幕 + 对角位移」，去掉箭头、高光与内屏渐变，几何对齐像素网格（4 倍超采样后降采样）。配色沿用母版（深屏 `#2B303C`、蓝屏 `#2E8AF0`、机身 `#E9EFF9` / `#F6FAFF`、描边 `#AABDD9`）。

托盘与标题栏是 16–24px 的主战场，这版在任务栏、通知区、Alt+Tab 里都能一眼认出「两块屏幕」。32px 及以上仍是用户提供的原插画，两者构图一致，切换尺寸不会跳。

| 文件 | 说明 |

## 6. 实现说明（已落地）

```bash
dualswitch ui            # 图形界面
dualswitch ui --dry-run  # 演练：只记日志，不发 Set
start-ui.bat             # 双击启动（pythonw，无控制台）
```

### 6.1 代码结构

```
src/dualswitch/ui/
├─ theme.py      设计 token + QSS（与本文第 4 节一一对应）
├─ widgets.py    TitleBar / Led / DeviceCard / HeroCard / ListRow / StatusBar / ToggleSwitch / Glyph
├─ window.py     MainWindow：状态卡 + 两台设备 + 排障列表
├─ settings.py   SettingsWindow：常规 / 热键 / 显示器 / 高级
├─ runner.py     QApplication + QSystemTrayIcon + 热键 + SwitchController 接线
└─ assets/       windows-logo(.png/-dim.png)、apple-logo(.png/-dim.png)
```

### 6.2 关键取舍

| 决策 | 原因 |
|---|---|
| 窗口用 PySide6，托盘也用 **QSystemTrayIcon**（不用 pystray） | 一个事件循环，避免 Qt 与 pystray 抢主线程 |
| `dualswitch run`（pystray）保持原样 | 无窗口模式不引入 Qt 依赖，老路径零风险 |
| 无边框窗口 + 自绘标题栏 | 与设计稿一致；关闭 = 收进托盘，退出只在托盘菜单 |
| 切换状态用 **250ms 轮询** controller，而不是回调 | 热键路径（controller.trigger）与界面路径共用同一套状态，不用改 `app.py` |
| 官方 OS 图标预渲染成 PNG（正常 / 置灰各一份） | 运行时不需要 SVG 渲染；置灰版直接用 `grayscale + alpha .38` 烘进图里，像素可控 |
| 界面不碰 DDC | 只调 `controller.switch_now()` / `backend.list_monitors()`，线程模型沿用原设计 |

### 6.3 已验证

- 64 个用例全绿（新增 4 个离屏 UI 用例：资源解析、两态切换、设置保存、非法输入拦截）。
- 真机启动、窗口渲染、托盘常驻、`--dry-run` 下点击切换 → 界面状态同步（`[演练] 未真正发送指令`）。
- 保存设置 → 校验 → 落盘 → 按需重建热键。
- 界面截图由 Qt 自己 `grab()` 产出（`design/windows/app-preview.png` 等），与真机一致。

### 6.4 落地时的两处微调

| 位置 | 问题 | 处理 |
|---|---|---|
| 设置页分段选择器 | 选中态白底只有 12px 高、文字左右无内边距，白底把文字切掉一半 | `#tab` 加 `padding: 0 12px`，按钮纵向 `Expanding` 撑满 24px 轨道 |
| 状态栏 | 设置页要显示完整 `config.json` 路径，超出宽度被硬裁 | 新增 `ElidedLabel`（中间省略、`resizeEvent` 重算），`setText` 仍收完整文本，调用方无需改 |
