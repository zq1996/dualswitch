# 剪贴板页 · 界面设计

> 2026-10-18 · 应用显示名 **屏幕切换**
> 可交互稿：`design/clipboard/index.html`
> 　`?page=clip` 直接进剪贴板页 · `?empty=1` 看空态 · 打开后点标题栏的剪贴板图标可翻页
> 依赖：`docs/UI-DESIGN.md`（Windows 外观）、`docs/UI-DESIGN-MAC.md`（mac 交互）、`docs/PLATFORM-SPLIT.md`（分层）
> 契约：`docs/CLIPBOARD-SYNC-CONTRACT.md`（数据从哪来）

---

## 1. 一条硬规则：不新增窗口

> **整个应用只有一个窗口。** 剪贴板是它的一个页面，和「设置」同级，翻进去、再返回。

这条不是审美偏好，是约束。多一个窗口在系统层面要付的代价：

| 代价 | 具体表现 |
|---|---|
| 任务栏 / 程序坞多一项 | 用户要在两个入口之间建立"哪个窗口是哪个"的心理映射 |
| 多一套位置记忆 | 用户移动过一个窗口，另一个还在原位，下次打开就乱 |
| 多一处"关了但进程还在" | 主窗口关=收进托盘，面板关=也要收进托盘，两套 closeEvent |
| mac 上多一层 | 面板是独立窗口时，⌘W 关掉它只是回到"谁都没有"，用户得再点一次主窗口 |

而这个工具的主窗口本身是**低频**的（99% 时间用户只用热键和托盘）。
低频界面再分层，用户就得记"我要找的东西在哪个窗口里"——这是把简单的事做复杂。

**所以：`QStackedWidget` 里加一页，不加窗口。**

## 2. 两端入口不一样，按各自的习惯

同一个 `MainWindow` 有两套 chrome，入口规则天生不同，**不要强行统一**：

| | Windows | macOS |
|---|---|---|
| 窗口外框 | 自绘标题栏（44px，含最小化/关闭） | 系统标题栏（红绿灯） |
| 设置入口 | **标题栏齿轮** | **列表里的「设置… ⌘,」行** |
| 剪贴板入口 | **标题栏图标**（齿轮左边） | **列表里的「剪贴板」行** |
| 主页面列表 | 3 行（探测/日志/诊断） | 5 行（探测/日志/诊断/剪贴板/设置…） |
| 主窗口高度 | 600（不变） | 620（多一行，`EXTRA_H = 20`） |

**为什么 Windows 放标题栏**：标题栏本来就是工具条（齿轮在那儿），剪贴板与它同级；
而且这样主页面列表**一点没动**，视觉零风险。

**为什么 mac 放列表**：mac 没有自绘标题栏，标题栏里塞按钮会像 Windows 应用。
mac 的列表本来就是"功能入口区"（设置也在里面），多一行是最自然的做法。
代价是列表 4 行变 5 行，窗口要加高 20px——只加 mac 的，用 chrome 字段，不动 Windows。

### 实现上怎么表达

```python
# chrome/win.py
INLINE_CLIPBOARD_ROW = False     # 入口在标题栏
EXTRA_H = 0

# chrome/mac.py
INLINE_CLIPBOARD_ROW = True      # 入口在列表
EXTRA_H = 20

# window.py
if self.chrome.INLINE_CLIPBOARD_ROW:
    rows.append(ListRow("clip", "剪贴板", "⌘⇧V", last=...))
if self.titlebar is not None:      # Windows 自绘标题栏才有
    self.titlebar.clipboardClicked.connect(...)
```

**面板主体 `ui/clipboard_page.py` 两端完全共用**，里面不出现 `sys.platform`。

| 区域 | 高度 | 规格 |
|---|---:|---|
| 标题栏 | 44 | **不新增**，复用主窗口；文字变 `屏幕切换 · 剪贴板` |
| 页头 | 40 | 左「‹ 返回」，中页名，右连接状态（绿点 + 对端名） |
| 列表 | max 252 | 行高 52，4 行可见 + 第 5 行露 20px；可滚 |
| 预览区 | flex（约 176） | **固定不跳动**，吃掉剩余高度 |
| 操作栏 | 48 | 复制到本机 / 重发 / 清空记录（右） |
| 状态栏 | 34 | 复用 `StatusBar`：左隐私说明，右条数 |

**页头为什么 40 而不是 44**：它比标题栏低一级，用 40 保持层级；同时省出的 4px 给列表。

**为什么要「‹ 返回」而不是面包屑/侧边栏**：三个页面（主 / 剪贴板 / 设置）都是"进去看一眼就回来"，
平级堆叠或常驻导航会把低频操作变成常驻视觉噪音。一个返回按钮足够，且和设置页的返回是同一套。

## 4. 状态语义

| 状态 | 何时出现 | 视觉 | 可操作 |
|---|---|---|---|
| 已同步 | 对端写入成功并回 ACK | 绿字 `#0E7C4A` / 浅绿底，无图标 | 无 |
| 传输中 | 已发出待 ACK，或正在传 | 蓝字 `#1E4FD8` + 百分比 | 可取消；>5s 降级为失败 |
| 仅本机 | 未配对 / 同步关闭 / 对端离线 | 灰字 `#7C8698`，最低权重 | 点药丸重试 |
| 失败 | 超时、对端拒绝、写入失败 | 红字 `#A82B2B`，整行可点 | 点药丸直接重试 |

**「仅本机」和「失败」必须分开。** 前者是"你还没连上另一台"，不是错误，不该报警；
后者是"连上了但没成"，需要用户介入。混成一个灰状态，用户就永远不知道到底传没传。

**状态药丸本身就是重试按钮**（失败 / 仅本机态），别让人先去底部找按钮。

## 5. 行规格

| 元素 | 规格 |
|---|---|
| 高 | 52（比主页面列表行的 42 高 10，因为要放两行文字） |
| 缩略图 | 36×36，圆角 7；图片 `object-fit:cover`；文本用等宽字体 **T** |
| 主行 | 12.5px；文本用等宽字体（代码要能看出缩进），图片写尺寸 |
| 副行 | 10.5px `#818B9C`，`来源 · 时间 · 大小 · 类型`，2px 圆点分隔 |
| 来源 | **加粗**（`Mac` / `Windows` / `本机`）—— 最容易看错的一列 |
| 状态药丸 | 10px，`padding 2px 6px`，`radius 5` |
| 选中 | 背景 `#F3F7FF` + 左侧 2.5px 主色条；**不加边框**（会和 hover 混） |
| 删除 | 行尾 ×，仅 hover 显示 |

**>8MB 的图片不画缩略图**，直接显示尺寸文字。为画一个 36px 方块解码 8MB PNG 不值得，
而且这种图多是 Retina 全屏截图，缩略图也看不出内容。

## 6. 预览区

| 类型 | 呈现 | 提示文案 |
|---|---|---|
| 图片 | 等比缩放（不裁切），最大 414×176，1px 边框 + 轻投影 | `双击查看原图` |
| 文本 | 白底框，11.5px / 行高 1.65，等宽字体，超长可滚 | `可直接选中文本` |

高度固定。按内容自适应会导致切到长文本时窗口长高、切到短文本缩回去，视线要重新定位。

## 7. 空态

| 空态 | 触发 | 文案 |
|---|---|---|
| 已配对无记录 | 有 `psk`，但还没传过 | 「还没有内容 / 复制点什么，然后按热键切一次屏」 |
| 未配对 | 没有 `psk` | 「两台机器连上才能互通」+ **「显示配对码」「手动填 IP」两个按钮** |

空态时**收起列表、预览和操作栏**，内容在整页垂直居中。
否则会出现"上面一块空白、下面一块空白、按钮点了没反应"的荒谬界面。

## 8. 交互与键盘

| 操作 | 行为 |
|---|---|
| 单击行 | 选中 + 更新预览（不打开、不复制） |
| 双击行 | 复制到本机剪贴板 |
| `↑` `↓` | 切换选中 |
| `Enter` | 复制选中项 |
| `⌫` / `Delete` | 删除选中项 |
| `⌘/Ctrl+C` | 复制选中项 |
| `Esc` / `‹ 返回` | 回主页面 |
| 点失败/仅本机的药丸 | 重试该条 |

键盘只在**列表有焦点**时生效，避免和全局热键、输入框抢键。

## 9. 边界与规则

**记录规则**：只在「同步动作发生时」记一条，不做"剪贴板一变就记"——后者会让每复制一个字就多一条。
没配对时也不记录，否则面板里堆满永远传不出去的本地内容。

**清空分两层**：

| 操作 | 位置 | 影响 | 可反悔 |
|---|---|---|---|
| 清空记录 | 操作栏右侧（红字） | 只清列表，**不动系统剪贴板** | 可以（内容还在剪贴板里） |
| 清空本机剪贴板 | 选中行右键菜单 | 系统操作 | 不可以 |
| ~~清空对端~~ | **不提供** | — | — |

**敏感内容**：命中 `org.nspasteboard.ConcealedType`（mac）/ `ExcludeClipboardContentFromMonitorProcessing`（win）
的内容既不传输也不记录，列表里连占位都不留。

**容量**：最近 10 条，内存环形缓冲，退出即清。不落库——一旦落盘就要处理加密、清理、磁盘占用，
收益（多记几条历史）不值。

**页面生命周期**：进入页面时启动 300ms 刷新定时器，离开时停掉。
不可见时不做任何 UI 更新，避免低频页面在后台空转。

## 10. 实现映射

| 文件 | 归属 | 改动 |
|---|---|---|
| `ui/clipboard_page.py` | **macOS 端**（共享代码） | 新增：`ClipboardPage(QWidget)`，约 200 行，用 `chrome()` 取外壳 |
| `ui/window.py` | macOS 端 | 加 `attach_clipboard()` / `show_clipboard_page()` / `on_clipboard_page()`，与 settings 那套对称 |
| `ui/runner.py` | macOS 端 | 实例化页面 + 返回信号 + 菜单信号接线（约 20 行） |
| `ui/chrome/base.py` | macOS 端 | 契约加 `INLINE_CLIPBOARD_ROW` / `EXTRA_H` 两个字段 |
| `ui/chrome/win.py` | **Windows 端** | 标题栏加剪贴板按钮（约 12 行）+ 两个新字段 |
| `ui/chrome/mac.py` | macOS 端 | 列表加一行 + 两个新字段 |
| `ui/settings.py` | macOS 端 | 「剪贴板」页签：开关 / 配对状态 / 查看记录入口 |
| `sync/engine.py` | macOS 端 | `records()` 返回面板要的数据 |

页面接口（与 `SettingsWindow` 同构，便于 window.py 复用同一套逻辑）：

```python
class ClipboardPage(QWidget):
    backRequested = Signal()      # 点「‹ 返回」
    def __init__(self, engine, parent=None)
    def refresh(self) -> None     # 300ms 定时器 / 进入页面时各调一次
```

页面只依赖一个数据结构（`engine.records()` 提供）：

```python
@dataclass
class ClipRecord:
    id: str              # = ClipItem.digest
    kind: str            # text | image
    text: str | None
    png: bytes | None    # 只在预览时解码，列表用缓存缩略图
    width: int
    height: int
    source: str          # "local" | "remote"
    peer_name: str
    ts: float
    state: str           # ok | pend | fail | local
    progress: float      # 0..1，仅 pend 有意义
    size: int
```
