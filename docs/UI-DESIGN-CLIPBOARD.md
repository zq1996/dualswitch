## 1. 设计前提

先明确这个面板**不是**什么：它不是剪贴板管理器（不做无限历史、不做搜索、不做收藏）。
它只回答三个问题，答完就关：

| 用户的问题 | 面板的回答 |
|---|---|
| 刚才那一下传过去了没？ | 每行的状态药丸：已同步 / 传输中 / 仅本机 / 失败 |
| 我十分钟前复制的那段代码在哪？ | 最近 10 条记录，按时间倒序 |
| 传错了 / 不想留了，删掉 | 单条 ×、清空记录、清空本机剪贴板 |

从这三个问题推出全部约束：

| 约束 | 推导 |
|---|---|
| 99% 的时间用户看不见它 | 不做引导动画、不做首次使用教程；打开就是内容 |
| 用户是在"切屏之后"才打开它 | 必须能看出**内容来自哪台机器**，否则分不清是刚复制的还是对端传过来的 |
| 判断"传没传过去"是最高频需求 | 状态必须独立成列，不能塞进副标题里让用户读句子 |
| 图片是截图，缩略图看不出内容 | 必须有预览区，且等比缩放（不裁切） |
| 内容可能有密码 | 敏感内容不传输、不记录、列表里连占位都不留 |
| 看完就走 | 关闭 = 隐藏，不销毁；再次打开保留滚动位置 |

## 2. 形态决策：独立窗口，不是设置里的第 5 页

| 方案 | 窗口尺寸 | 问题 |
|---|---|---|
| 塞进设置窗口做第 5 页签 | 440×600，内容区约 400 | 列表 + 预览最少要 440 高，塞不下；缩到 3 行可见就失去"回溯"价值 |
| **独立面板（选定）** | **520×620** | 多一个窗口类，但列表能放 4 行 + 预览 186px |

**代价与收益**：多写一个 `ui/clipboard_panel.py`（约 220 行）＋ 两端菜单各加一项（各 5 行）。
换来的是这个页面真的能用——塞进设置里会变成一个谁也懒得打开的页面。

### 入口（两端各归各的，不冲突）

| 平台 | 入口 | 归属文件 |
|---|---|---|
| Windows | 托盘右键菜单「剪贴板…」 | `ui/chrome/win.py`（Windows 端改） |
| macOS | 菜单栏菜单「剪贴板…」（`⌘⇧V`）＋ 主窗口「剪贴板」行 | `ui/chrome/mac.py`（macOS 端改） |
| 两端 | 设置 → 剪贴板页签的「查看记录…」按钮 | `ui/settings.py`（macOS 端改） |

面板主体 `ui/clipboard_panel.py` 是**共享代码**，用 `chrome()` 拿外壳，不出现 `sys.platform`。

| 区域 | 高度 | 关键规格 |
|---|---:|---|
| 标题栏 | 44 | Win 自绘；mac 用系统标题栏（高度自动，总高会多 ~22） |
| 连接条 | 44 | 状态灯 8px + 对端名 + 连接方式 + 右侧同步模式标签 |
| 列表 | max 252 | 行高 59，可滚；第 5 行露 16px 提示还有内容 |
| 分界线 | 1 | `#E5E9F1` |
| 预览区 | 186 | 固定高度，**不随选中项跳动**；标题行 24 + 内容 138 |
| 操作栏 | 54 | 主 / 次 / 危险三段 |
| 底部说明 | 30 | 隐私说明常驻，不做成 tooltip |

用户视线要重新定位。固定 186 让"列表位置不动"，只用眼睛扫下方。

## 4. 状态语义（整个面板最需要读懂的东西）

| 状态 | 何时出现 | 视觉 | 可操作性 |
|---|---|---|---|
| 已同步 | 对端写入成功并回了 ACK | 绿字 `#0E7C4A` / 浅绿底，无图标 | 无 |
| 传输中 | 已发出待 ACK，或流式传输进行中 | 蓝字 `#1E4FD8` + 百分比 | 可取消；>5s 降级为失败 |
| 仅本机 | 未配对 / 同步关闭 / 对端离线 | 灰字 `#7C8698`，最低权重 | 点药丸重试 |
| 失败 | 超时、对端拒绝、写入失败 | 红字 `#A82B2B`，**整行可点** | 点药丸直接重试 |

**「仅本机」和「失败」必须分开。** 前者是"你还没连上另一台"，不是错误，不该报警；
后者是"连上了但没成"，需要用户介入。混成一个灰状态，用户就永远不知道到底传没传。

**状态药丸是按钮。** 失败态点药丸即重试，不要让用户先去底部找按钮再回来。

## 5. 行规格

```
┌────┬──────────────────────────────────────┬────────┐
│ 40 │ 内容摘要（一行，超出省略）              │ 状态   │
│    │ 来源 · 时间 · 大小 · 类型              │ 药丸   │
└────┴──────────────────────────────────────┴────────┘
```

| 元素 | 规格 |
|---|---|
| 缩略图 | 40×40，圆角 7；图片 `object-fit:cover`；文本用等宽字体 **T** |
| 内容摘要 | 12.8px；文本用等宽字体（代码要能看出缩进），图片写尺寸 |
| 副行 | 11px `#818B9C`；`来源 · 时间 · 大小 · 类型` 用 2px 圆点分隔 |
| 来源 | **加粗**，`Mac` / `Windows` / `本机`——这是用户最容易看错的信息 |
| 状态药丸 | 10.5px，`padding 2.5px 7px`，`radius 5` |
| 选中行 | 背景 `#F3F7FF` + 左侧 2.5px 主色条；**不加边框**（会和 hover 混） |
| hover 删除 | 行尾 ×，仅 hover 显示；`opacity 0 → 1` |

**图片超过 8MB 时列表不画缩略图**，直接显示尺寸文字。为画一个 40px 方块去解码 8MB PNG，不值得；
而且这种大图往往是 Retina 全屏截图，缩略图也看不出内容。

## 6. 预览区

| 内容类型 | 呈现 | 交互 |
|---|---|---|
| 图片 | 等比缩放，最大 420×138，带 1px 边框 + 轻投影 | 双击打开原图（系统看图器） |
| 文本 | 白底框，12px / 行高 1.7，等宽字体（若原来就是代码） | 可直接选中复制；超长可滚 |
| 空 | `选中一条查看预览` | — |

右上角固定提示：图片 → `双击查看原图`，文本 → `可直接选中文本`。
**提示要写"能做什么"，不写"这是什么"。**

## 7. 空态

两种，语义完全不同：

| 空态 | 触发 | 版式 | 文案重点 |
|---|---|---|---|
| 未配对 | 没有 `clipboard.psk` | 连接条灰灯 + `未配对` 标签；正文给**配对按钮** | 告诉用户下一步做什么（两台都打开面板，输同一个 6 位码） |
| 已配对无记录 | 配对了但还没传过东西 | 连接条绿灯 + 空列表 + 居中图标 | 告诉用户它是活的（复制点什么，切一次屏） |

空态时**收起预览区和操作栏**，列表区撑满（502px），内容垂直居中。
否则会出现"上面一块空白、下面一块空白、按钮点了没反应"的荒谬界面。

## 8. 交互与键盘

| 操作 | 行为 |
|---|---|
| 单击行 | 选中 + 更新预览（不打开、不复制） |
| 双击行 | 复制到本机剪贴板 |
| `↑` `↓` | 切换选中 |
| `Enter` | 复制选中项到本机 |
| `⌫` / `Delete` | 删除选中项 |
| `⌘/Ctrl+C` | 复制选中项 |
| `Esc` | 关闭面板 |
| 点状态药丸（失败/仅本机） | 重试该条 |

键盘只在**列表获得焦点**时生效，避免和主窗口的热键、输入框抢键。

## 9. 边界与规则

**记录规则**：只在「同步动作发生时」记一条，不做「剪贴板一变就记」。
后者会让用户每复制一个字就多一条，面板立刻变成噪音。
没配对时也不记录——否则面板里会堆满永远传不出去的本地内容。

**清空有两个，语义必须分开**：

| 操作 | 位置 | 影响范围 | 可反悔 |
|---|---|---|---|
| 清空记录 | 底部右侧按钮（红色文字） | 只清列表，**不动系统剪贴板** | 可以（内容还在剪贴板里） |
| 清空本机剪贴板 | 选中行右键菜单 | 系统操作 | 不可以 |
| ~~清空对端~~ | **不提供** | — | — |

> 不提供"清空对端"：能远程清别人剪贴板的工具，没人会放心用。

**敏感内容**：命中 `org.nspasteboard.ConcealedType`（mac）或
`ExcludeClipboardContentFromMonitorProcessing`（win）的内容，既不传输也不记录，
列表里连占位都不留。用户从密码管理器复制后切屏，面板应该看起来像什么都没发生。

**容量**：最近 10 条，内存环形缓冲，退出即清。不做落库——
一旦落盘就要处理加密、清理、磁盘占用，收益（多记住几条历史）完全不值。

**大图**：>8MB 不画缩略图；>32MB 直接不传输（`MAX_IMAGE_BYTES` 已经在契约里定死）。

**窗口行为**：关闭 = 隐藏，不销毁，保留滚动位置与选中项。
mac 上关闭面板后菜单栏图标仍在；Windows 上关闭后托盘图标仍在。

## 10. 实现映射

| 文件 | 归属 | 改动 |
|---|---|---|
| `ui/clipboard_panel.py` | **macOS 端**（共享代码） | 新增：面板窗口，约 220 行，用 `chrome()` 拿外壳 |
| `ui/chrome/win.py` | **Windows 端** | 托盘菜单加一项「剪贴板…」→ 发信号 |
| `ui/chrome/mac.py` | **macOS 端** | 菜单栏菜单加一项「剪贴板…」`⌘⇧V` |
| `ui/settings.py` | **macOS 端** | 加「剪贴板」页签：同步开关 + 配对状态 + 「查看记录…」 |
| `ui/runner.py` | macOS 端 | 面板实例化 + 菜单信号接线（约 15 行） |
| `sync/engine.py` | macOS 端 | 提供 `records()` 返回面板要的数据 |

面板只依赖一个数据结构（由 `engine.records()` 提供，Windows 端不用管）：

```python
@dataclass
class ClipRecord:
    id: str              # 等于 ClipItem.digest
    kind: str            # text | image
    text: str | None
    png: bytes | None    # 只在预览时解码
    width: int
    height: int
    source: str          # "local" | "remote"
    peer_name: str       # 显示用：MacBook Pro
    ts: float
    state: str           # ok | pend | fail | local
    progress: float      # 0..1，仅 pend 有意义
    size: int
```

刷新方式：面板可见时用 300ms 定时器拉 `engine.records()`（和现有状态轮询同频），
不可见时停掉。**不做信号推送**——剪贴板记录变化频率低，轮询足够，且避免跨线程 UI 更新。
